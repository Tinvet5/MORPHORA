# MORPHORA V4.8.5 — Developer Validation Guide

## Daily command

Before committing content or code:

```bash
npm run check
```

A successful exit code means there are no blocking validation errors. Warnings should still be reviewed.

## Focused commands

```bash
npm run check:js
npm run check:models
npm run check:validation
npm run check:static
npm run schema:check
npm run validate:project
```

`npm run validate:atlas` keeps the older V4.8.4 atlas validator available for comparison, but `validate:project` is authoritative in V4.8.5.

## Diagnostics page

Use Live Server and open:

```text
/dev-tools.html
```

The page performs a browser-side project traversal. It is useful for quickly spotting fetch/path problems in the same HTTP environment used by the app.

The CLI validator is still authoritative because a browser cannot reliably inspect every repository file or enumerate all Deep Zoom tiles.

## Severity

### ERROR

A release blocker. Examples:

- malformed JSON.
- JSON Schema failure.
- duplicate IDs.
- unsafe repository path.
- published image missing.
- published DZI tile missing.
- invalid label coordinates.
- invalid quiz radius.
- stale application version references.

### WARNING

Content is valid enough to continue development but should be reviewed. Examples:

- draft/coming-soon photograph is not present yet.
- non-production naming style.
- image metadata mismatch that does not prevent loading.
- editorial metadata missing from a non-blocking context.

### PASS

A recorded project-level check completed successfully.

## Validation reports

Generated by `npm run validate:project`:

```text
reports/validation-report.json
reports/validation-report.txt
```

The JSON report has this shape:

```json
{
  "validatorVersion": "4.8.5",
  "generatedAt": "...",
  "summary": {
    "errors": 0,
    "warnings": 1,
    "passes": 3
  },
  "counts": {},
  "issues": []
}
```

Reports are local build products and ignored by Git.

## GitHub Actions

Every push and pull request runs the same `npm run check` pipeline. The workflow uploads the validation reports as artifacts.

While GitHub Pages still publishes directly from a branch, validation is advisory after a direct push. Do not treat a push as a release until the validation workflow is green. V4.8.6 is the planned milestone for making validated CI the actual deployment gate.
